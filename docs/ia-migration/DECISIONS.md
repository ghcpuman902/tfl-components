| **J10 Board config schema (2026-08-14)**                               | Typed Board settings are defined in `lib/tfl/board-settings.ts` (app layer). Components export defaults and accept ID-keyed props; they do **not** own URL grammar. Hash params are add-only and forward-compatible (unknown keys ignored). Namespaces: flat shell params (`stop`, `stopName`, `mode`, `fit`, `key`); `a.*` arrivals; `s.*` reserved for status. Compact positional lists (`a.rows=6,2,2`) zip by effective line order in the Board layer into stable `pageSizeByLine` maps — never a fragile positional array on the installable component. Defaults omitted on serialize. Semantic breaks introduce a new param name (or a future `v`); old names keep parsing with their old meaning or are ignored. Arrivals-line config and status-line data stay separate. Layout stays CSS-first (`className` / `classNames` never URL-configurable).                                                                                                                                                                                                                                                                                                            |

Every unattended panel has a configured fixed height across live, empty, and error states; overflow paginates inside it. Automatic height fitting remains out of scope.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

| **J15 Arrivals paging and refresh contract (2026-08-17)**              | Interactive arrivals stay live and manually pageable: new fetches update values and ordering on the current page. After inactivity on a non-first page, return to page 1; mouse, touch, swipe, click, and keyboard reset the timer, and hover or focus suspends it. Unattended pinned rotation pins the first arrival and chunks the rest into windows of `pageSize - 1`, overlapping only a short final window. This replaces the pinned `slide` / `jump` sequence in [`unattended-boards.md`](../unattended-boards.md) and removes `pinAdvance` / `a.pinAdvance`. Network polling, countdown updates, and frame dwell stay separate: adopt the latest ordering only at a frame boundary; countdown may update in place; dwell does not shorten with frame count. Arrival React keys use a composite of TfL service fields, not `sourceIndex`, rank, or countdown. No built-in row-movement animation and no mixed mode. This supersedes the arrivals sequencing and refresh parts of J14 and the earlier unattended-boards pinned example. J14's Board-wide `interactive` / `unattended` toggle, hybrid component boundary, and status-surface decisions still stand. |

Unattended pages advance automatically; counts update in place, while changed membership and order wait for a page boundary. One page stays static and has no paging chrome. The map keeps ratio markers, takes a fixed height in whole Board tiles, and does not join the sequence. This closes the Cycle hire question left open by J14.                                                         |
