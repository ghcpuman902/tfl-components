## What install does

The shadcn CLI does not add a sealed npm package for the board. It **copies source into your app** — components, helpers, assets, and CSS tokens — so you can edit everything. `tfl-ts` arrives as a normal dependency; the visuals are yours.

### Recommended

```bash
pnpm dlx shadcn@latest add https://tfl.manglekuo.com/r/tube-status-board.json
```

One URL is enough. The board pulls its TfL graph with absolute registry URLs (`line-badge`, `tfl-roundel`, colour tokens). Official shadcn atoms (`button`, `skeleton`, `dialog`, `tooltip`) still come from the default registry.

Browse other items on the [Components catalogue](/docs/components).

### What to expect

A Status board install typically walks four steps:

1. **Checking registry** — resolves the board JSON and each dependency URL.
2. **Installing dependencies** — npm packages such as `tfl-ts` and `lucide-react`.
3. **Creating files** — on the order of a dozen-plus paths under `components/`, `lib/`, and `public/` (exact count depends on what you already have).
4. **Updating `app/globals.css`** — injects TfL colour tokens (`data-line`, OKLCH line colours).

If a UI atom already exists, the CLI may skip it and say so (`button` is a common skip). Use `--overwrite` only when you intend to replace local copies.

### Files you will see

After a clean Status board install, expect something like:

```
components/ui/skeleton.tsx
components/ui/tooltip.tsx
components/ui/dialog.tsx
components/ui/button.tsx          # often skipped if already present
components/tfl/brand/line-badge.tsx
components/tfl/brand/tfl-roundel.tsx
components/tfl/status/tube-status-board.tsx
lib/tfl/status-types.ts
lib/tfl/roundel-presets.ts
lib/tfl/brand-colours.ts
lib/tfl/brand-rules.ts
lib/tfl/brand.ts
public/transit-logos/*.svg
```

Roundel artwork under `public/transit-logos/` is optional decoration for mode presets; the board runs without you wiring those images by hand.

```tsx
import { TubeStatusBoard } from "@/components/tfl/status/tube-status-board"
```

Pass **normalised** line-status rows as `data`. Fetching stays in your app — not inside the board.

### What you still configure

Register at the [TfL API portal](https://api-portal.tfl.gov.uk/) and set server-side env:

```env
TFL_APP_ID=your-app-id
TFL_APP_KEY=your-app-key
```

Keep keys off the client and out of reusable components. Until credentials exist, use fixture or cached rows so the board still renders.

| Source | Use |
|--------|-----|
| **Cached data** | Site / app cache for general demos |
| **Fixture data** | Deterministic states (severe delays, empty boards) |
| **Live data** | Developer credentials in the application layer |

### Optional: `@tfl` namespace

Installing several items? Register the URL template once in `components.json`:

```json
{
  "registries": {
    "@tfl": "https://tfl.manglekuo.com/r/{name}.json"
  }
}
```

Then:

```bash
pnpm dlx shadcn@latest add @tfl/tube-status-board
```

The zero-config full URL above remains the shortest path for a first install.
