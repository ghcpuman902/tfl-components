## Installation

Copy a component into your Next.js app with the shadcn CLI. The registry item declares `tfl-ts` and any UI dependencies.

### Recommended

```bash
pnpm dlx shadcn@latest add https://tfl-components.vercel.app/r/tube-status-board.json
pnpm dlx shadcn@latest add https://tfl-components.vercel.app/r/arrivals-board.json
pnpm dlx shadcn@latest add https://tfl-components.vercel.app/r/line-strip.json
pnpm dlx shadcn@latest add https://tfl-components.vercel.app/r/tfl-roundel.json
pnpm dlx shadcn@latest add https://tfl-components.vercel.app/r/line-badge.json
```

| Item | Command |
|------|---------|
| Status board | `…/r/tube-status-board.json` |
| Arrivals | `…/r/arrivals-board.json` |
| Line strip | `…/r/line-strip.json` |
| Roundel | `…/r/tfl-roundel.json` |
| Line badge | `…/r/line-badge.json` |

### Legacy compatibility names

Older docs referred to `live-arrivals-board` and `bus-arrivals-board`. Those registry JSON files still exist for migration, but they are **not** recommended products. Prefer `arrivals-board` and keep fetch/polling in your app.

### API keys

Register at the [TfL API portal](https://api-portal.tfl.gov.uk/) and set:

```env
TFL_APP_ID=your-app-id
TFL_APP_KEY=your-app-key
```

Keys stay on the server. Do not place credentials inside reusable components.

### Example data vocabulary

| Source | Use |
|--------|-----|
| **Cached data** | Site / app cache for general demos |
| **Fixture data** | Deterministic states (severe delays, empty boards) |
| **Live data** | Developer credentials in the application layer |
