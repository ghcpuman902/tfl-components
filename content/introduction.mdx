## Introduction

**tfl-components** is the visual layer of a TfL developer environment. Together with [`tfl-ts`](https://www.npmjs.com/package/tfl-ts) (data) and this site, the goal is to discover London transport information, retrieve it cleanly, inspect normalised shapes, and render useful interfaces.

You copy component source with the shadcn CLI — not a locked npm UI package.

### Two layers in `tfl-components`

1. **Data-aware interfaces** — accept (or responsibly obtain) normalised `tfl-ts` data and render useful transport UI.  
2. **Rendering primitives** — presentational building blocks from explicit values; discoverable when you need control.

Highest-value path: **get data → render**.

Shared brand language lives in **Foundations**. **Maps** split geographic vs schematic. **Explore** explains what TfL knows. **Tools** are playgrounds; **Drafts** incubate experiments.

See `docs/TARGET_ARCHITECTURE.md` (frozen Stage 1).

### Distribution

```bash
pnpm dlx shadcn@latest add https://tfl-components.vercel.app/r/tube-status-board.json
```

Put `TFL_APP_ID` and `TFL_APP_KEY` in your server environment. See [Installation](/installation).

### How this site is organised

- **Start** — introduction and install  
- **Explore** — information model and relationships  
- **Interfaces** — data-aware embeddable boards  
- **Primitives** — lower-level visual control  
- **Foundations** — colours, identity, licensing  
- **Maps** — geographic vs schematic/network  
- **Tools** — inspect / tune / debug playgrounds  
- **Drafts** — incubation
