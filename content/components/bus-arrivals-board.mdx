## Purpose

Bus stop departures. `BusArrivalsBoard` interprets `RealtimePrediction[]` and owns bus defaults: one flat list in arrival-time order, [`BusNumberChip`](/docs/bus-number-chip) on every row, stop letter on the header. Tube and rail use [`RailArrivalsBoard`](/docs/tube-rail-arrivals). The two share row chrome and the tile rhythm, not the high-level API.

Fetching, caching, polling, and stop discovery stay in the app. Nearby / search lives under [Explorer → Bus stops](/explore/bus-stops). That explorer composition is `BusArrivals`, not this board.

## Getting data with tfl-ts

```ts
import TflClient from "tfl-ts"

const tfl = new TflClient({
  appId: process.env.TFL_APP_ID!,
  appKey: process.env.TFL_APP_KEY!,
})

const stopId = "490000091G"
const [stop, data] = await Promise.all([
  tfl.stopPoint.get(stopId),
  tfl.stopPoint.getArrivals({
    stopPointIds: [stopId],
    sortBy: "timeToStation",
  }),
])
```

`get` returns the stop (`commonName`, `stopLetter`). `getArrivals` returns `RealtimePrediction[]`. Pass both through; the board sorts arrivals itself.

## Render

```tsx
import { BusArrivalsBoard } from "@/components/tfl/arrivals/bus-arrivals-board"

<BusArrivalsBoard
  data={data}
  stopName={stop.commonName}
  stopLetter={stop.stopLetter}
/>
```

The default is flat: no route headers, no route colour bars, interleaved route numbers in soonest-first order.

## Variations

### Group by route

Pass `groupBy="route"` when you want route sections (the homepage proof board does this). Routes sort in stable natural numeric order (`9` before `18` before `205`). Arrivals inside each route sort by `timeToStation`. Each section uses a bus-red bar and repeats the route chip on every row. Hover a route group for next/previous arrows on the route header.

<BusArrivalsGroupedVariant />

```tsx
<BusArrivalsBoard
  data={data}
  stopName={stop.commonName}
  stopLetter={stop.stopLetter}
  groupBy="route"
/>
```

### Ordering

Named policies, not comparator callbacks:

| Prop | Default | `"source"` |
|------|---------|------------|
| `groupBy` | `none` (flat list) | — |
| `sortBy` | `timeToStation` | Input order (global when flat, per route when grouped) |
| `groupSortBy` | `route` (natural numeric) | First appearance in `data` |

`groupSortBy` only applies when `groupBy="route"`. `maxRows` is a per-route cap when grouped (it does not drop later routes) and a list cap when flat. `pageSize` (default 3) pages extra arrivals — arrows on the route header when grouped, or in a trailing tile (right-aligned, empty left) when flat. Equal `timeToStation` keeps input order. The board does not mutate `data`.

### Baseline grid

Same `--arrivals-unit` / `--arrivals-row` tiles as rail, so a bus board beside a rail board lines up. The stop letter is a red circle next to the stop name, not a per-row field.

### Polling

Keep polling outside the board, then update `data`. Optional `statusLabel` shows poll metadata.

## Behaviour / edge cases

| Prop | Type | Description |
|------|------|-------------|
| `data` | `readonly RealtimePrediction[]` | Normalised arrivals from `tfl-ts`. Missing/`undefined` → empty. |
| `groupBy` | `"none" \| "route"` | Flat list (default) or route sections. |
| `sortBy` | `"timeToStation" \| "source"` | Arrival order. |
| `groupSortBy` | `"route" \| "source"` | Route-group order when grouped. |
| `stopName` | `string` | Board heading. Fits via abbr/scale. |
| `stopLetter` | `string` | Stop letter — red circle next to the stop name. |
| `loading` / `error` | … | Loading and error presentation. Prefer a short human `error` string. |
| `emptyKind` | `"empty" \| "ended" \| "offline"` | Why the board has no rows when `error` is unset. Resolve in the app (`resolveArrivalsEmptyKind`). Night buses still run, so prefer `empty` over `ended`. |
| `emptyMessage` | `string` | Optional copy override for `emptyKind`. |
| `statusLabel` | `string` | Optional poll / refresh caption. |
| `maxRows` | `number` | Prediction cap after ordering. Per route when grouped; whole list when flat. Headers do not count. |
| `pageSize` | `number` | Visible arrivals per page (default 3). Grouped: arrows on the route header. Flat: trailing tile, right-aligned. |

## Data ownership

Fetching, caching, polling, geolocation, and API credentials stay in the application layer. This component only renders.
