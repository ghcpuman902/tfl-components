## Getting the data

Status comes from `tfl-ts` via `line.getStatus`. You can fetch yourself:

```ts
import TflClient from "tfl-ts"

const tfl = new TflClient({
  appId: process.env.TFL_APP_ID!,
  appKey: process.env.TFL_APP_KEY!,
})

const lineStatuses = await tfl.line.getStatus({
  modes: ["tube", "elizabeth-line", "dlr", "tram", "overground"],
})
```

Or let the board fetch for you through `getTflClient()` (recommended path today). Prefetch-as-props APIs may land later; the board remains the same concept either way.

## Render

```tsx
import { TubeStatusBoard } from "@/components/tfl/status/tube-status-board"

export default function Page() {
  return <TubeStatusBoard />
}
```

Omit `lineIds` to load all tube / Elizabeth / DLR / tram / Overground modes.

## Variations

### Batch by line IDs

`DEFAULT_STATUS_LINE_IDS` is all 11 Underground lines plus Elizabeth (12 total):

```tsx
import {
  DEFAULT_STATUS_LINE_IDS,
  TubeStatusBoard,
} from "@/components/tfl/status/tube-status-board"

export default function Page() {
  return <TubeStatusBoard lineIds={DEFAULT_STATUS_LINE_IDS} />
}
```

### Custom subset

```tsx
const MY_LINES = ["central", "northern", "victoria", "jubilee"] as const

export default function Page() {
  return <TubeStatusBoard lineIds={MY_LINES} />
}
```

### Hide header

Pass `hideHeader` when a parent layout already provides a title.

## Behaviour

| Prop | Type | Description |
|------|------|-------------|
| `lineIds` | `readonly string[]` | Optional. When set, one batched status request for these IDs. |
| `hideHeader` | `boolean` | Omit the board header when a parent layout already has one. |
| `children` | `ReactNode` | Optional slot below the status list. |

- Severity sorting and official colours come from `tfl-ts`.
- Status is cached for ~60s via Next.js Cache Components.
- Covers Underground, Overground, Elizabeth line, DLR, and Tram — the tube & rail family.
