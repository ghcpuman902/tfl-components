## Purpose

Severity-sorted service status board for TfL Tube & Rail — Tube, Elizabeth line, Overground, DLR, and Tram (Cable Car is separate on TfL’s status surface). Embed when you already have normalised line status rows from `tfl-ts`.

## Getting data with tfl-ts

```ts
import TflClient, { sortLinesBySeverityAndOrder } from "tfl-ts"

const tfl = new TflClient({
  appKey: process.env.TFL_APP_KEY!,
})

const data = sortLinesBySeverityAndOrder(
  await tfl.line.getStatus({
    modes: ["tube", "elizabeth-line", "dlr", "tram", "overground"],
  }),
)
```

`data` is the public `tfl.line.getStatus()` row type (aliased in this repo as `StatusLine`). No docs-site-only transformation.

On this docs site, `getCachedLineStatuses` in `@/lib/tfl/status-data` wraps the same idea with Cache Components (**Cached data**).

## Render

```tsx
import { TubeStatusBoard } from "@/components/tfl/status/tube-status-board"

export default function Page({ data }) {
  return <TubeStatusBoard data={data} />
}
```

The board does **not** fetch.

## Variations

### Curated Underground + Elizabeth IDs

```tsx
import {
  DEFAULT_STATUS_LINE_IDS,
  TubeStatusBoard,
} from "@/components/tfl/status/tube-status-board"
import { getCachedLineStatuses } from "@/lib/tfl/status-data"

export default async function Page() {
  const data = await getCachedLineStatuses(DEFAULT_STATUS_LINE_IDS)
  return <TubeStatusBoard data={data} />
}
```

### Hide header

Pass `hideHeader` when a parent layout already provides a title.

## Behaviour / edge cases

| Prop | Type | Description |
|------|------|-------------|
| `data` | `readonly StatusLine[]` | Rows from `tfl.line.getStatus()`. Missing/`undefined` renders empty. |
| `hideHeader` | `boolean` | Omit the board header when a parent layout already has one. |
| `children` | `ReactNode` | Optional slot below the status list. |

- Severity sorting should happen before pass-in (`sortLinesBySeverityAndOrder`).
- Official colours come from `tfl-ts` CSS helpers inside the board.

## Data ownership

Credentials, fetch, and cache live in the app. Fixtures can demonstrate severe delays without live disruption.
