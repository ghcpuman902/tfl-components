## Purpose

Data-aware molecular line / route diagram. Accept prepared spine or schematic values derived from `tfl-ts` route data, apply colour / label recipes / closures, then compose `StraightStrip` or `BranchStrip`.

`StraightStrip` and `BranchStrip` remain rendering primitives for explicit visual control. Prefer `LineStrip` when you have TfL line data.

## Getting data with tfl-ts

Fetch a route sequence in your app (or use the site helper), prepare stations, then pass a spine:

```ts
import { getLineSpine } from "@/lib/tfl/line-spine"

const spine = await getLineSpine("victoria")
```

`getLineSpine` uses `tfl.line.getRouteSequence` / stop points under the hood. Fetching stays outside `LineStrip`.

You can also pass explicit `stations` prepared with `toDiagramStation` from stop-point data.

## Render

```tsx
import { LineStrip } from "@/components/tfl/diagram/line-strip"

export default function Page({ spine }) {
  return <LineStrip lineId="victoria" spine={spine} fit />
}
```

Branched schematic:

```tsx
<LineStrip
  lineId="northern"
  schematic={NORTHERN_LINE_SCHEMATIC_HORIZONTAL}
  lineColor={getLineColor("northern").hex}
/>
```

## When to drop to primitives

| Need | Use |
|------|-----|
| TfL line data, label recipes, closures, colour | `LineStrip` (this page) |
| Linear corridor with already-prepared stations | [`StraightStrip`](/interfaces/line-strip) via atom import |
| Branched schematic with prepared nodes | [Branch strip](/primitives/branch-strip) |
| Station label fitting only | [Station name](/primitives/station-name) |

## Part closures

For “no service between A and B”, mute the **track** with `segments`. `LineStrip` derives station greys with the all-adjacent-closed rule. Disabled stations and segment states remain reusable rendering capabilities on the strip atoms.

## Data ownership

Do not put credentials or polling inside `LineStrip`. Prepare spine / schematic in the app or a Block (see [Week ahead](/blocks/week-ahead)).
